# 二进制版本差异

1. 记录两份构建的来源标识、格式、架构及版本信息，确认比较的是对应产物。如果构建类型或编译选项不明，把它们记为限制。
2. 先比较导入、导出和模块列表。对用户关心的功能，以可见符号为首选匹配线索。缺少符号时，结合字符串引用、调用关系和数据形状配对；单凭地址、偏移或文本相似度无法确认同一函数。
3. 把不同布局、重定位、内联等可能的编译差异与有证据的接口或行为变化分开。对照两边的关键分支与可观察输出，描述对文件兼容性、接口调用或诊断信息的影响。
4. 输出匹配项、变化项、对应证据和置信度。只比较指定版本，保持产物原样。归纳兼容性影响，不还原可用于利用的补丁细节。
