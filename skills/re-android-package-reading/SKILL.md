# Android 应用包结构阅读

1. 确定用户要理解的应用功能，并记录包名、版本、目标 API 级别和样本标识。优先使用已导出的 Manifest、类列表、资源表或本地静态分析记录。只有宿主已有相应能力时，才读取 APK 所需的元数据。
2. 从清单中确认应用入口和与问题相关的活动、服务、接收器或内容提供器。结合 intent filter、权限要求和目标 API 级别解释组件声明。仅有权限声明时，将它记作可能能力。
3. 用已提供的代码片段、类名、资源 ID 或匹配的原生库记录建立关联。区分已确认的引用、资源声明和待验证的运行时行为。对混淆名称保留原始符号与证据。
4. 输出组件表和相关调用方向。保持样本原样，不安装、不运行、不注入，也不绕过签名、访问控制或平台限制。
